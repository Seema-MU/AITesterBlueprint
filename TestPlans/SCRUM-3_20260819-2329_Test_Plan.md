# 1. Document & Release Overview

## 1.1 Purpose

This Test Plan defines the QA strategy, scope, test approach, risks, and release criteria for validating **JIRA SCRUM-3** ("add items to cart page", Priority: Medium, Type: Task, Status: To Do).

The feature: a dedicated "Add Items to Cart" page where users can browse products, view details, select quantities, and add multiple items to their shopping cart in a single workflow — replacing the current single-product-page-only flow.

## 1.2 Release Overview

Per the PRD attached to SCRUM-3, this release delivers:

* A responsive product grid (4 per row desktop / 2 tablet / 1 mobile)
* Product cards with image, name, SKU, price, stock badge, star rating, quantity control, Add to Cart
* Real-time footer cart summary (item count, subtotal) + View Cart / Continue Shopping
* Live search by name/SKU (no page reload) with matching count
* Add-to-cart toast with 4s auto-dismiss
* Error states with retry (products load failure, add-to-cart failure)
* Session retention: cart valid 24h; anonymous users via localStorage, logged-in users in DB

# 2. Objectives & Scope

## 2.1 Test Objectives

* Validate all 7 acceptance criteria groups (AC1–AC7) from the PRD are met.
* Verify the add-to-cart workflow end to end: browse → search → quantity → add → cart summary update.
* Validate stock-state handling (In Stock / Low Stock / Out of Stock incl. disabled add button).
* Validate error handling and retry behavior for product-load and add-to-cart API failures.
* Validate cart persistence: 24h session, localStorage for anonymous, DB for logged-in.
* Validate performance targets: page load < 2s, search < 500ms, add-to-cart < 1s.
* Validate responsive behavior and the browser matrix (Chrome 90+, Firefox 88+, Safari 14+, Edge 90+).
* Validate WCAG 2.1 AA accessibility (per PRD DoD).

## 2.2 In Scope

### Functional

* Grid layout & responsiveness (AC1)
* Header: title, breadcrumb, search bar (AC1)
* Product card contents (AC2)
* Quantity input (1–999) + +/- buttons, default 1 (AC3)
* Add to Cart, Out-of-Stock disabled state (AC3)
* Toast success + 4s auto-dismiss (AC3)
* Footer summary real-time update, View Cart → /cart, Continue Shopping (AC4)
* Search by name/SKU, real-time, no reload, match count (AC5)
* Error states + retry (AC6)

### Integration

* `GET /api/v1/products`, `GET /api/v1/products/search`, `POST /api/v1/cart/items` (per PRD)
* Cart persistence (localStorage vs DB by login state)

### Data

* Quantity boundary values (1, 999, 0, 1000, empty, non-numeric)
* Cart summary math (item count, subtotal before tax/shipping)

### Platforms

* Browsers: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
* Viewports: desktop, tablet (≤1024px), mobile (≤640px)

### Non-Functional

* Performance: Yes (page load < 2s, search < 500ms, add < 1s)
* Security: Yes (cart/session handling, API payload validation)
* Accessibility: Yes (WCAG 2.1 AA per DoD)
* Compatibility: Yes (browser matrix)

## 2.3 Out of Scope

* Wishlist, product recommendations, coupon codes, gift wrapping (explicitly out of scope in PRD)
* Backend cart-service implementation beyond the 3 documented endpoints
* Payment / checkout flow
* Performance/load testing beyond the stated targets

# 3. Product & Quality Risk Overview

## 3.1 Product Overview

* **Application:** E-commerce "Add Items to Cart" page
* **Architecture:** React 18+, Redux state, Product Service v1.0+ APIs, feature flag for rollout
* **User types:** Anonymous shoppers (localStorage cart) and logged-in users (DB-persisted cart)
* **External systems:** Product Service API, cart API

## 3.2 Critical Business Flows

* Browse → add item(s) → cart summary updates → View Cart
* Search → add item → cart
* Add-to-cart API failure → error + retry
* Cart persistence across session (anonymous and logged-in)

## 3.3 Quality Risks

| Risk | Impact | Probability | Risk Level | Mitigation |
| ---- | ------ | ----------- | ---------- | ---------- |
| Cart summary math incorrect (count/subtotal) | High | Medium | High | Boundary + multi-item math tests |
| Quantity edge cases (0, 999, 1000, non-numeric) mis-handled | High | Medium | High | Boundary testing on quantity input |
| Add-to-cart API failure path untested | High | Low | Medium | Error + retry scenarios |
| 24h cart session expiry breaks user flow | Medium | Medium | Medium | Persistence/expiry tests |
| Search perf > 500ms or reloads page | Medium | Medium | Medium | Perf + no-reload assertions |
| Responsive breakpoint defects | Medium | Medium | Medium | 3-viewport matrix tests |

## 3.4 Risk-Based Testing Prioritization

P0: add-to-cart core flow, quantity boundaries, cart summary math, stock states. P1: search, error/retry, persistence, performance targets. P2: visual/UX polish, edge interactions.

# 4. Test Strategy

## 4.1 Overall Testing Approach

Risk-based layered testing: API-level validation of the 3 endpoints, component/UI validation of cards and controls, E2E validation of the browse→add→summary workflow, plus performance and accessibility checks.

## 4.2 Test Levels

| Test Level | Purpose | Primary Owner |
| ---------- | ------- | ------------- |
| Unit Testing | Validate card/quantity/reducer logic | Development |
| API/Service Testing | Validate the 3 cart/product endpoints | QA/Development |
| Integration Testing | Validate page ↔ API integration | QA/Development |
| System Testing | Validate complete page behavior | QA |
| End-to-End Testing | Validate browse→add→cart workflow | QA |
| UAT | Validate business acceptance | Business/Product |

## 4.3 Test Types

Functional, Integration, Regression, Smoke, API, UI, Database (cart persistence), Exploratory, Compatibility, Performance, Accessibility.

## 4.4 Test Design Approach

* Positive scenarios (AC1–AC7 happy paths)
* Negative (out-of-stock add, invalid quantity, API failures)
* Boundary (quantity 1/999/0/1000, empty, non-numeric)
* State transitions (stock badge states, toast lifecycle)
* Integration failures (products API down, add API down)
* Role/data combinations (anonymous vs logged-in)

## 4.5 Regression Strategy

Regression covers existing product pages and cart flows that the new page touches: existing product detail add-to-cart (the "before" flow), cart page render, and shared cart state. Verify the new page does not break the existing single-product add flow.

# Gaps & Questions for the author

Findings from the requirement gap-analysis (✅ present / ⚠️ ambiguous / ❌ missing).

## ❌ Missing / blocking

1. **Ticket body is only images** — the SCRUM-3 description contains just the attached images; all requirements live in the attached `sample_prd_add_to_cart.md`. Confirm that PRD is authoritative (it references a different ticket id, "SHOP-1245", and project — is that intentional or a copy-paste artifact?).
2. **Cart page destination unspecified** — AC4 says View Cart navigates to `/cart`, but the cart page itself is out of scope here. Confirm the `/cart` target exists and is testable, or that navigation is only to be smoke-checked.
3. **No test data or environments defined** — products (all stock states), accounts (anonymous + logged-in), and API availability must be provisioned.
4. **Feature flag behavior** — rollout plan mentions a feature flag + rollback; confirm whether QA tests with the flag on, and how to verify the flag-off state.

## ⚠️ Ambiguous

5. **SKU format mismatch** — mockup uses `PRD-001…`, screenshot uses `SKU-001…`. Which is authoritative?
6. **Discount badges** — screenshot shows "10% off" etc., but the PRD has no discount field. Is discounted pricing in scope, and does subtotal include discounts?
7. **Quantity input constraints** — PRD says 1–999 via number field OR +/- buttons. Confirm: does the field clamp/reject out-of-range, and what error (if any) shows for 0/1000/non-numeric?
8. **Search match count placement** — AC5 says results show matching count, but the mockup has no visible count element. Where should it appear?
9. **"Low Stock" threshold** — how many units trigger the Low Stock badge?
10. **Duplicate-add behavior** — adding the same product twice: does it merge quantities (e.g., 1 then 2 → 3) or create separate line items?
11. **Anonymous→login merge** — if an anonymous cart exists and the user logs in, does the localStorage cart merge into the DB cart?
12. **Toast a11y** — should the toast be announced to screen readers (role="status"/aria-live)? Not specified.

## ✅ Present (usable as-is)

- AC1–AC7 with checkable criteria
- API endpoint contracts (paths, request/response shapes)
- Performance targets (< 2s, < 500ms, < 1s)
- 24h cart retention policy, localStorage vs DB
- Browser matrix (Chrome 90+, Firefox 88+, Safari 14+, Edge 90+)
- Design assets (colors, font), out-of-scope list, DoD checklist
